# وب‌سایت شرکتی مبتنی بر Yii2

این پروژه بر پایه Yii 2 Advanced ساخته شده و برای اجرا با PHP 8.2 و
Yii 2.0.55 به‌روزرسانی شده است.

## پیش‌نیازها

- PHP 8.2 به همراه افزونه‌های `mbstring`، `openssl`، `pdo_mysql` و `fileinfo`
- Composer 2
- MySQL یا MariaDB با پشتیبانی از `utf8mb4`

فعال‌کردن افزونه‌های `zip`، `intl` و `gd` نیز توصیه می‌شود. افزونه `gd` برای
نمایش CAPTCHA لازم است.

## نصب محلی

```powershell
composer install
php init --env=Development --overwrite=All
```

فایل تنظیمات محیطی را بسازید و مقادیر آن را تغییر دهید:

```powershell
Copy-Item .env.example .env
```

رمز دیتابیس و رمز مدیر فقط در `.env` قرار می‌گیرند و این فایل وارد Git نمی‌شود.
دیتابیس خالی را ایجاد کنید:

```powershell
C:\xampp\mysql\bin\mysql.exe -u root -e "CREATE DATABASE yii2_website CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
```

سپس محیط و دسترسی پوشه‌ها را بررسی و migrationها را اجرا کنید:

```powershell
php yii install/check
php yii migrate --interactive=0
php yii seed
```

فرمان `seed` تنظیمات پایه، مدیر ارشد و در حالت پیش‌فرض یک نوشته نمونه ایجاد
می‌کند. برای نصب بدون محتوای نمونه از `php yii seed 0` استفاده کنید.

## اجرا

برنامه را با وب‌سرور داخلی PHP اجرا کنید:

```powershell
php yii serve --docroot=frontend/web 127.0.0.1:8080
```

## چندزبانه‌سازی

زبان پیش‌فرض سایت و زبان مستقل پنل مدیریت در فایل `.env` قابل تنظیم‌اند:

```dotenv
APP_LANGUAGE=fa
ADMIN_LANGUAGE=fa
```

صفحات عمومی با پیشوند زبان مانند `/fa/blog` و `/en/blog` در دسترس هستند. برای افزودن
زبان جدید، فقط مشخصات آن را در `frontend/config/params.php` اضافه کنید و فایل پیام
`frontend/messages/<locale>/app.php` را بسازید؛ تغییری در کنترلرها یا URLها لازم نیست.
جهت صفحه، مقدارهای `lang` و `dir`، لینک‌های `hreflang` و انتخاب‌گر زبان از همین تنظیمات
تولید می‌شوند. محتوای ترجمه‌شده بلاگ، دسته‌بندی و تنظیمات متنی نیز در جدول
`content_translation` ذخیره می‌شود و در صورت نبود ترجمه از زبان fallback استفاده می‌کند.

## سیستم طراحی رابط کاربری

رابط کاربری از design system داخلی پروژه در `frontend/web/css/design-system.css` استفاده
می‌کند. رنگ‌ها، فاصله‌ها، تایپوگرافی، دکمه‌ها، فرم‌ها، پیام‌ها، جدول‌ها، کارت‌ها،
وضعیت‌های loading و empty و breakpointهای موبایل با CSS custom property تعریف شده‌اند.
Asset سراسری سایت Bootstrap یا Materialize را بارگذاری نمی‌کند و رفتارهای navigation،
alert و loading در فایل کوچک `frontend/web/js/app.js` پیاده‌سازی شده‌اند.

هنگام توسعه صفحه جدید از tokenها و componentهای همین design system استفاده کنید تا
پشتیبانی responsive، دسترس‌پذیری و RTL/LTR بدون CSS پراکنده حفظ شود.

داده‌های نمایشی نصب شامل سه نمونه‌کار و یک تصویر hero بهینه‌شده با فرمت WebP است. این
assetها در `frontend/web/img/portfolio` قرار دارند و با اجرای `php yii seed` به‌صورت
idempotent به داده‌های نمونه متصل می‌شوند.

- سایت: <http://127.0.0.1:8080/>
- مدیریت: <http://127.0.0.1:8080/admin>

در Apache یا XAMPP باید Document Root روی `frontend/web` تنظیم شود. ریشه مخزن
نباید به‌صورت عمومی در دسترس وب قرار بگیرد.

## بررسی سلامت نصب

```powershell
php requirements.php
php yii install/check
composer validate --no-check-publish
composer security:audit
composer lint
composer style
composer analyse
composer test:prepare
composer test
composer test:install
```

ساخت دیتابیس صرفاً از طریق migration انجام می‌شود و پروژه هیچ وابستگی‌ای به
فایل dump قدیمی ندارد.

## مدیریت منوها

مدیران دارای مجوز `manageMenus` می‌توانند از مسیر `/admin/menu` منوی اصلی یا فوتر را مدیریت کنند. هر آیتم
دارای عنوان چندزبانه، مسیر داخلی یا URL خارجی، والد، ترتیب نمایش، مقصد لینک و وضعیت انتشار است. منوی اصلی
پس از ایجاد اولین آیتم منتشرشده، به‌صورت خودکار جایگزین منوی پیش‌فرض می‌شود. مسیرهای داخلی مانند `/contact`
با زبان فعال سایت تولید می‌شوند و URLهای خارجی فقط با پروتکل HTTP یا HTTPS پذیرفته می‌شوند.

## صفحات پویا، انتشار و SEO

مدیریت صفحات از مسیر `/admin/page` در دسترس کاربران دارای مجوز `managePages` است. هر صفحه عنوان، نامک،
خلاصه، محتوای چندزبانه و تصویر شاخص دارد. نامک با حروف کوچک لاتین، اعداد و خط تیره تعریف می‌شود و صفحه در
نشانی‌هایی مانند `/fa/company` و `/en/company` نمایش داده می‌شود.

وضعیت‌های انتشار شامل پیش‌نویس، منتشرشده و زمان‌بندی‌شده است. زمان شروع و پایان انتشار اختیاری است و صفحات
پیش‌نویس، زمان‌بندی‌شده آینده یا منقضی‌شده از سایت و نتایج جست‌وجو حذف می‌شوند. تنظیمات SEO هر صفحه شامل
عنوان و توضیحات، کلمات کلیدی، canonical URL و robots است و متاتگ‌های Open Graph نیز تولید می‌شوند.

## کتابخانه رسانه

کتابخانه رسانه در `/admin/media` و با مجوز `manageMedia` قابل استفاده است. فرمت‌های PNG، JPEG، GIF، WebP
و PDF تا سقف ۱۰ مگابایت پذیرفته می‌شوند. MIME واقعی فایل کنترل و نام ذخیره‌شده توسط سرور تولید می‌شود؛
بنابراین فایل‌های PHP، HTML و اجرایی قابل بارگذاری نیستند. URL عمومی هر رسانه برای استفاده در محتوا نمایش
داده می‌شود و تصویرها را می‌توان به‌عنوان تصویر شاخص صفحه انتخاب کرد.

## جست‌وجوی سایت

جست‌وجوی عمومی از مسیر `/fa/search` یا `/en/search` در دسترس است و عنوان، خلاصه و محتوای صفحات منتشرشده
و نوشته‌های وبلاگ را در زبان فعال بررسی می‌کند. عبارت جست‌وجو باید بین ۲ تا ۱۰۰ نویسه باشد و محتوای
پیش‌نویس یا خارج از بازه انتشار در نتایج ظاهر نمی‌شود.

## ایمیل و اعلان فرم‌ها

تنظیمات SMTP، فرستنده، گیرنده اعلان و فعال‌بودن اعلان فرم‌های تماس، سفارش و همکاری از مسیر
`/admin/setting/email` مدیریت می‌شود. رمز SMTP به‌صورت رمزنگاری‌شده ذخیره می‌شود و در فرم مدیریت دوباره
نمایش داده نمی‌شود. حالت File Transport برای توسعه و آزمایش بدون ارسال ایمیل واقعی در دسترس است.

## فعالیت مدیران و خروجی داده

تمام درخواست‌های پنل مدیریت همراه با مدیر، مسیر، روش HTTP، IP، User-Agent و زمان در گزارش فعالیت ثبت می‌شوند.
گزارش در `/admin/audit` و خروجی CSV فرم‌ها و صفحات در `/admin/export` قرار دارد. گزارش فعالیت به permission
`viewAudit` و خروجی‌ها به `exportData` محدود هستند و عملیات دانلود با POST انجام می‌شود.

## Cache و Maintenance Mode

ابزارهای پاک‌سازی Cache و asset و فعال‌سازی Maintenance Mode در `/admin/setting/system` قرار دارند. در حالت
تعمیر، صفحات عمومی پاسخ 503 و پیام قابل تنظیم می‌دهند اما ورود و پنل مدیریت برای رفع مشکل در دسترس می‌ماند.

## Backup و Restore

پشتیبان کامل دیتابیس از `/admin/backup` با فرمت JSON نسخه‌دار دریافت می‌شود. Restore فقط برای نقش
`superAdmin`، با درخواست POST، تأیید صریح، محدودیت اندازه و اعتبارسنجی جدول‌ها و ستون‌ها فعال است. بازیابی
تمام داده‌های فعلی برنامه را جایگزین می‌کند؛ فایل پشتیبان را فقط از منبع مورد اعتماد بارگذاری کنید.

## پرسش‌های متداول

مدیریت چندزبانه FAQ از `/admin/faqs` انجام می‌شود و ترتیب نمایش و وضعیت انتشار هر پرسش قابل تنظیم است.
صفحه عمومی `/fa/faqs` یا `/en/faqs` تنها پرسش‌های منتشرشده را با رابط accordion واکنش‌گرا نمایش می‌دهد.
